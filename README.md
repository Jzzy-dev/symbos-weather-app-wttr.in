# wttr.in for SymbOS (MSX2)

Shows the standard 125-column wttr.in report, with its colours, in a SymbOS
window. It uses a custom 4×8 font (125 × 4 px = 500 px wide) and the
16-colour palette. The whole content area is used for the report; there is no
toolbar.

Menus:

- **Location**
  - **Choose city...** opens a small modal dialog with a text field. Return
    means OK and Escape means Cancel. The field is prefilled with the current
    city, fully selected, so typing replaces it.
  - **My location (IP)** lets wttr.in guess your location from your IP address.
  - **Refresh**
- **View**: 3-day report, narrow day/night layout, today only, or current
  conditions only.

The title bar shows which location is displayed. The status bar shows the
download size or any network/HTTP error.

`test/default.png` is rendered from wttr.in's own test output using the exact
line buffers the app builds. The preview scales pixels 2×4 to match MSX2
aspect.

## Files

| File | What it is |
|---|---|
| `wttr.c` | The SymbOS app: report window, menus, city dialog, HTTP/1.0 fetch, event loop |
| `ansi.c`, `ansi.h` | Converts wttr.in output into `C_TEXT_CTRL` lines: UTF-8 → font bytes, ANSI SGR → `0x01 fg<<4\|bg` colour codes. Plain C, so it also builds with gcc. |
| `font4x8.h`, `glyphmap.h`, `colmap.h` | Generated by `tools/mkfont.py` (font, Unicode map, 256→16 colour table) |
| `tools/mkfont.py` | Edit glyphs and colour overrides here, then rerun it |
| `tools/preview.py` | Renders line buffers to a PNG, as SymbOS would draw them |
| `test/` | Host test harness and wttr.in golden output samples |

## Build

With SCC (Windows: from the SCC `bin` folder, or with it on your PATH):

```
cc wttr.c ansi.c -lnet -N "wttr.in"
```

This produces `wttr.exe`. Copy it to the MSX, start the Network Daemon, and
run it. You can pass a start city: `wttr.exe Amsterdam`. With an empty field,
wttr.in guesses your location from your IP address.

After changing glyphs or colours:

```
python3 tools/mkfont.py
gcc -I. -o test/render_test test/render_test.c ansi.c
./test/render_test test/data/default.txt test/default.bin
python3 tools/preview.py test/default.bin test/default.png   # needs Pillow
```

## Design notes

- **One `C_TEXT_CTRL` per line.** This control supports inline colour changes
  (`0x01 NN`) and custom fonts, so no bitmap canvas is needed. A full-screen
  canvas would far exceed the 16 KB segment limit. Line text and the font must
  share the data segment, which ends up at 11.3 KB of 16 KB.
- **Colour codes are only emitted when they would be visible.** Spaces don't
  switch the foreground colour. The longest line uses 174 of its 200 bytes.
- **The app uses its own HTTP/1.0 client, not `HTTP_GET()`.** In current SCC
  `src/lib/libnet/http.c`, the line
  `if (_safegte(...));` has a stray semicolon, so `HTTP_GET` stops after the
  first ~1.4 KB of the body. It also speaks HTTP/1.1 without chunked decoding.
  HTTP/1.0 gets a plain body and a server-side close. This is worth reporting
  upstream.
- **The city field is in a dialog, not the toolbar.** In v1 the field sat in
  the toolbar and never received keystrokes. Keyboard focus appears to go
  only to controls in a window's content area, so the field now lives in the
  dialog's content area with `focusctrl` pointing at it.
- **Query flags:** `?mAF` means metric, force ANSI regardless of User-Agent,
  and no "Follow" footer. The View menu appends `n`, `1` or `0`.
- **Colour mapping:** nearest colour in the SymbOS palette, plus a few hand
  overrides (light cloud → white, dark cloud → grey, sun → bright yellow, rain
  → light blue). The temperature scale comes out as bands: blue, cyan, green,
  yellow, orange, red.

## Not yet tested on hardware

This compiles cleanly with SCC, and the parser and font are tested on the host
against real wttr.in output. Things to check on a real MSX2 or in openMSX:

1. **Window size.** It's set to 504 px content width. If SymbOS clamps it,
   maximise the window or reduce `MARGIN`.
2. **Non-ASCII in the city field.** SymbOS characters above 127 are sent
   %-encoded as single bytes, but wttr.in expects UTF-8.
3. **Blocking fetch.** The UI waits while fetching (a few seconds). Moving
   `http_get()` to a thread with `thread_start()` is the next step for a
   responsive window and a Cancel button.
